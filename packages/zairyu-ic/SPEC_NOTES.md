# 在留カード IC 仕様メモ(0-2)

入管庁の公開仕様書3点を読み、実装に必要な事項と3様式の差分をまとめる。

| 略称 | 仕様書 | 版 | 対象カード |
| --- | --- | --- | --- |
| legacy | 在留カード等仕様書(一般公開用) | Ver1.5(令和6年3月) | 在留カード・特別永住者証明書(旧様式) |
| gen2 | 第２世代在留カード等仕様書(一般公開用) | Ver1.1(令和8年4月) | 第２世代在留カード・第２世代特別永住者証明書 |
| tokutei | 特定在留カード等仕様書(一般公開用) | Ver1.1(令和8年4月) | 特定在留カード・特定特別永住者証明書(個人番号カード一体型) |

仕様書は予告なく改訂されるため、入管庁サイトの正誤表を定期的に確認すること。

## 1. 3様式の差分表

| 項目 | legacy | gen2 | tokutei |
| --- | --- | --- | --- |
| カード種別(MF/EF02 タグ C1) | `1` 在留 / `2` 特永(1 バイト) | `05` / `06`(2 バイト) | `07` / `08` |
| 起動直後のカレント | MF | MF | 個人番号カード。在留 AP を SELECT する |
| 在留 AP の AID | — | — | `D3 92 F0 00 4F 01 00..00` |
| DF1 / DF2 / DF3 の AID | `D3 92 F0 00 4F 02/03/04 00..00`(16 バイト) | 同左 | 同左 |
| DF1 の中身 | EF01 券面(表)イメージ(D0, 7000)/ EF02 顔画像(D1, 3000) | EF01 番号(C2)/ EF02 券面記載事項(C5〜CD)/ EF03 氏名イメージ(D0, 2500)+顔画像(D1, 3000)/ EF04 住居地イメージ(DFD1, 2500) | gen2 と同じ |
| DF2 の中身 | EF01 住居地(D2〜D4)/ EF02 包括許可欄テキスト(D5)/ EF03 個別許可欄テキスト(D6)/ EF04 更新申請中(D7) | EF01 資格外活動(D5 区分・D6 期限・D7 個別有無)/ EF02 更新申請中(D8)/ EF03 その他(D9・DE) | gen2 と同じ |
| DF3 の中身 | チェックコード DA(256)+証明書 DB(1200 固定) | チェックコード DC(96)+証明書 DD(598〜599) | gen2 と同じ |
| アクセス権 | MF Free / DF1 番号認証+SM / DF2・DF3 番号認証 | 同左(DF1 は全 EF が SM) | 同左 |
| セッション鍵の確立 | GET CHALLENGE + MUTUAL AUTHENTICATE | 同左 | SET SESSION KEY(端末生成の鍵を RSA-OAEP で配送) |
| Kenc / Kmac | SHA-1(番号12バイト) の先頭16バイト | 同左 | 端末が任意に生成(セッションごとに変える) |
| 認証の暗号・MAC | 2-key TDES CBC / Retail MAC(ISO 9797-1 Alg.3, Pad 2) | AES-128 CBC / AES-CMAC 先頭8バイト | RSA 2048 OAEP(SHA-256) |
| KSenc | SHA-1(K.IFD⊕K.ICC‖00000001) の先頭16バイト | 同左 | = Kenc |
| SM の暗号 | TDES CBC, IV=0 | AES-128 CBC, IV=0 | AES-128 CBC, IV=AES(KSenc, N)。N は開始時 1、使うたびに +1 |
| SM の READ BINARY | `08 B0 P1 P2 00 00 04 96 02 XX XX 00 00` | 同左 | `08 B0 P1 P2 00 00 05 96 03 00 XX XX 00 00`。読出し長の上限がカードベンダーにより存在 → 分割読出し |
| 電子署名 | RSA 2048 PKCS#1 v1.5。復号結果 = パディング‖SHA-256(仕様書は DigestInfo なし。**実カードは DigestInfo 付き**) | ECDSA secp384r1 / SHA-256。チェックコード = r‖s(96) | gen2 と同じ |
| 署名対象 | 券面(表)イメージ値(7000)‖顔画像値(3000) | 券面記載事項(53)‖顔画像(3000)‖氏名イメージ(2500) | gen2 と同じ |
| 署名・顔画像がない年少者 | 16 歳未満 | 1 歳未満 | 1 歳未満 |

### 第2世代・特定の券面記載事項(DF1/EF02)

記載順に連結したものが署名対象(各項目を最大長まで 0x00 埋め)。特別永住者証明書は ★ が無く 34 バイトのため、19 バイトを 0x00 で埋めて 53 バイトにする。

| タグ | 長さ | 内容 |
| --- | --- | --- |
| C5 | 8 | 有効期限満了日(カード自体)YYYYMMDD |
| C6 | 8 | 生年月日 |
| C7 | 1 | 性別 1:男 2:女 3:不詳 |
| C8 | 3 | 国籍・地域コード |
| C9 | 10 | 在留資格コード |
| CE | 4 | 在留期間(YYMM / DDD / 無期限 0000) |
| CA ★ | 2 | 許可の種類コード |
| CB ★ | 8 | 許可年月日 |
| CC ★ | 1 | 就労制限 1:なし 2:在留資格に基づく就労のみ 4:指定書による就労のみ 9:就労不可 |
| CD ★ | 8 | 在留期間の満了日 |

## 3. 仕様書の不整合・あいまいな点

1. **タグ "DF D1"(gen2/tokutei の住居地イメージ)は厳密な BER-TLV ではない**。2 バイト目の b8 が 1 なので BER なら 3 バイト目以降もタグになる。仕様書 3.2.3.1 の「タグは 1〜2 バイト」に従い、パーサーはタグを最大 2 バイトで扱う(`strictBer: true` で厳密 BER)
2. **tokutei 別添2 手順10** は見出しが「DF1 および EF04 を選択」で EF-ID 0004 を選んでいるのに、続く手順11で氏名イメージ・顔画像(EF03)を読んでいる。EF03 の誤記とみて EF-ID 0003 を選択している → 実機で確認
3. **tokutei の SM カウンタ N**: 暗号データを持たないコマンド(READ BINARY)で N が進むかの記述がない。現実装は「暗号化・復号を行うたびに +1」(VERIFY で N=1、最初の読出し応答の復号で N=2…)→ 実機で確認
4. legacy 別添1 Step4 の MUTUAL AUTHENTICATE の INS が "84" と誤記(4.2.4 と別添2は "82")。gen2 で修正済み
5. legacy 3.3.5 注 *1 の「DF3/EF01 には D A 00 DB 00…」は顔写真なしの説明としては不自然(gen2 では DF1/EF02 に修正)
6. gen2/tokutei 3.4.3 図の「ハッシュ値(256 バイト)」は 256 ビットの誤記
7. legacy の READ BINARY 平文は Le が 3 バイト(拡張 APDU)。iOS Core NFC で拡張長 APDU が通るか実機で確認

## 5. 設計(DESIGN.md)への影響

- **旧様式の IC には文字情報がない**(券面イメージと顔画像のみ)。氏名・満了日・就労制限を IC から取り出して自動照合することはできない。番号は「番号から導出した鍵で認証が通った」ことで一致が確認できる。満了日等は OCR/手入力とし、IC の券面イメージと目視で照合する
- **第2世代・特定でも氏名は画像のみ**(氏名イメージ)。番号(C2)、満了日(CD)、カード有効期限(C5)、就労制限(CC)、在留資格(C9)、資格外活動(D5〜D7)はテキストで取れるので自動照合・自動入力できる。DESIGN.md 4章⑤の「氏名の一致を自動チェック」は、全様式で画像の目視確認に置き換える必要がある
- **画像形式**: 券面・氏名・住居地イメージは MMR 圧縮 TIFF(CCITT G4)、顔画像は JPEG2000。ブラウザや Android は標準で表示できないため、サーバー側で PNG/JPEG に変換して配信する(外部サービスには送らない)
- **番号違いの検出箇所**: legacy/gen2 は番号から鍵を作るため、番号が違うと VERIFY より前の MUTUAL AUTHENTICATE で失敗する。UI は「番号を確認してください」に誘導する
- **年少者カード**: 署名がないカード(legacy は 16 歳未満、gen2/tokutei は 1 歳未満)は署名検証できない。「署名なし」として扱い、偽造疑いとは区別する
- **特定在留カード**は上表 B の配送鍵が入手できるまで読めない。PoC の完了条件(3様式すべて)はこの入手が前提
