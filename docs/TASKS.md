## フェーズ0: PoC(IC読み取りと署名検証)

最大の技術リスク。ここが通らなければ設計を見直す。

- [ ] **0-1 モノレポ雛形**: pnpm workspaces + Turborepo、`apps/mobile`(Expo Development Build)、`apps/api`、`packages/zairyu-ic`、`packages/shared`。TypeScript strict、Vitest、ESLint
  - 完了条件: `pnpm test` が通り、mobile が実機(iPhone・Android)で起動する
  - 進捗: 雛形・`pnpm test`/`typecheck`/`lint`・CI は完了。Android の JS バンドルと prebuild(NFC 権限)は確認済み。**実機起動は未確認**
- [ ] **0-2 仕様書の読み込み**: 入管庁の3仕様書(在留カード等 Ver1.5 / 第二世代 / 特定在留カード等)から、AID、EF構成、認証手順、TLVタグ、署名データの範囲を `packages/zairyu-ic/SPEC_NOTES.md` に整理
  - 完了条件: 3様式の差分表がある
  - 進捗: 完了。差分表・不整合・未解決事項(発行者証明書、特定在留カードの配送鍵)・設計への影響を記載
- [ ] **0-3 TLVパーサーと署名検証**: `packages/zairyu-ic` に BER-TLV パーサー、券面(表)イメージ+顔画像の連結 → SHA-256 → PKCS#1 v1.5 署名検証を実装
  - 完了条件: 仕様書の例・テストベクタで単体テストが通る
  - 進捗: TLV パーサー、SM(TDES/AES)、鍵交換、読出しシーケンス、EF の解釈、署名検証(RSA/ECDSA P-384)を実装。鍵交換と SM は仕様書のコマンド例の値で一致を確認。署名検証は自己生成の鍵でのみ確認(仕様書に署名のテストベクタはない)
- [ ] **0-4 NFC読み取り(Android)**: IsoDep で番号認証 → セキュアメッセージング → EF読み出し
- [ ] **0-5 NFC読み取り(iOS)**: Core NFC ISO 7816。エンタイトルメントと `com.apple.developer.nfc.readersession.iso7816.select-identifiers` に対象AIDを記載
  - 進捗(0-4/0-5): NFC との接続(`apps/mobile/src/nfc.ts`)、PoC 画面、サーバーの署名検証エンドポイント(`poc.verifyIcRead`)を実装。Android/iOS の JS バンドルと iOS のエンタイトルメント生成を確認。**実機での読み取りは未実施**(手順は `docs/POC.md`)。特定在留カードは配送鍵の入手待ち
  - 実機結果(2026-11-20、Galaxy S23 + 旧様式の実カード): 読出し・署名検証に成功。仕様書との違いは SPEC_NOTES.md 3.1。iOS・第2世代・特定在留カードは未確認
  - 完了条件(0-4/0-5): サンプルカード(入管庁から貸与)または実カードで、3様式すべての読み出しと署名検証が成功。読み取り時間を計測
- [ ] **0-6 端末内OCR**: vision-camera + ML Kit でカード番号(英字2+数字8+英字2)を抽出、正規表現とチェックで誤読を弾く
  - 完了条件: 10枚以上で抽出成功率を記録
  - 進捗: vision-camera(v5)で撮影 → ML Kit テキスト認識(端末内)→ 番号抽出・誤読補正 → 一時ファイル削除を実装(`apps/mobile/src/ocr.ts`, `CardNumberScanner.tsx`)。OCR の正否を IC 認証の成否で数える計測を PoC 画面に追加。JS バンドルとネイティブ設定の生成は確認済み。**ネイティブビルドと実機での計測は未実施**(手順は `docs/POC.md`)

  - 進捗: サーバー側は完了(`apps/api/src/auth`、`routers/auth.ts`)。argon2id、ログイン失敗 10 回で 15 分ロック、管理者の TOTP 必須(初回に設定)とコード再利用防止、リフレッシュトークンのローテーションと再利用検知、IP 単位のレート制限、監査ログ。実 PostgreSQL の結合テストあり。アプリ側も実装(`apps/mobile/src/auth`: ログイン・TOTP 設定、リフレッシュトークンを SecureStore に保存、起動時と 30 秒以上離れたあとに生体認証で再ロック)。Android 実機でログインと TOTP 設定を確認(2026-11-20)。TOTP 秘密鍵の暗号化は暫定でローカル鍵(1-4 で Key Vault に置き換え)。レート制限はメモリ上(複数インスタンス化の前に共有ストアへ)

- [x] **1-4 暗号化**: Key Vault のテナント別鍵でカード番号・画像を暗号化。HMAC検索列。Blob の署名付きURL発行
  - 進捗: 完了(`packages/vault`、`apps/api/src/images.ts`)。エンベロープ暗号化(KEK は Key Vault、テナント鍵は包んで DB)、データ鍵のローテーション、HMAC 検索列。画像 URL は Blob の SAS ではなく API の 2 分有効の署名付き URL とし、発行時に権限・拠点・監査ログ、配信時に復号。Azure 実環境での接続は未確認(ローカル KEK・メモリ/ファイル保存でテスト)
- [x] **1-5 監査ログ**: 全変更系と画像閲覧を記録
  - 進捗: 完了。認証済みの変更系手続き(mutation)は `ctx.tenantTx` 内で `ctx.audit` を 1 件以上呼ばないとエラーになり、変更ごとロールバックされる(書き忘れを防ぐ)。記録は項目名のみで値は残さない。ログイン系・画像閲覧も記録。運営者の操作(1-19)は未対応
