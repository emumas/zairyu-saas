# 実装タスク

上から順に進める。各タスクは「完了条件」を満たしてから次へ。設計の根拠は `DESIGN.md`。

## フェーズ0: PoC(IC読み取りと署名検証)

最大の技術リスク。ここが通らなければ設計を見直す。

- [ ] **0-1 モノレポ雛形**: pnpm workspaces + Turborepo、`apps/mobile`(Expo Development Build)、`apps/api`、`packages/zairyu-ic`、`packages/shared`。TypeScript strict、Vitest、ESLint
  - 完了条件: `pnpm test` が通り、mobile が実機(iPhone・Android)で起動する
  - 進捗: 雛形・`pnpm test`/`typecheck`/`lint`・CI は完了。Android の JS バンドルと prebuild(NFC 権限)は確認済み。**実機起動は未確認**
- [ ] **0-2 仕様書の読み込み**: 入管庁の3仕様書(在留カード等 Ver1.5 / 第二世代 / 特定在留カード等)から、AID、EF構成、認証手順、TLVタグ、署名データの範囲を `packages/zairyu-ic/SPEC_NOTES.md` に整理
  - 完了条件: 3様式の差分表がある
  - 進捗: 差分表の枠のみ作成。仕様書 PDF が未入手のため中身は未記入
- [ ] **0-3 TLVパーサーと署名検証**: `packages/zairyu-ic` に BER-TLV パーサー、券面(表)イメージ+顔画像の連結 → SHA-256 → PKCS#1 v1.5 署名検証を実装
  - 完了条件: 仕様書の例・テストベクタで単体テストが通る
  - 進捗: TLV パーサー・署名検証・証明書チェックを実装し、自己生成の鍵と証明書でテスト済み。**仕様書のテストベクタでの確認は未実施**(0-2 待ち)
- [ ] **0-4 NFC読み取り(Android)**: IsoDep で番号認証 → セキュアメッセージング → EF読み出し
- [ ] **0-5 NFC読み取り(iOS)**: Core NFC ISO 7816。エンタイトルメントと `com.apple.developer.nfc.readersession.iso7816.select-identifiers` に対象AIDを記載
  - 完了条件(0-4/0-5): サンプルカード(入管庁から貸与)または実カードで、3様式すべての読み出しと署名検証が成功。読み取り時間を計測
- [ ] **0-6 端末内OCR**: vision-camera + ML Kit でカード番号(英字2+数字8+英字2)を抽出、正規表現とチェックで誤読を弾く
  - 完了条件: 10枚以上で抽出成功率を記録
  - 進捗: OCR テキストから番号を抽出・誤読補正する関数(`packages/shared` の `extractCardNumberCandidates`)のみ実装済み

## フェーズ1: MVP

### 基盤
- [ ] **1-1 DBスキーマ**: `DESIGN.md` 7章の全テーブルを Drizzle で定義。`tenant_id` と RLS ポリシー、`verifications`/`audit_logs` の UPDATE/DELETE 禁止
- [ ] **1-2 認証**: メール+パスワード(argon2)、TOTP、リフレッシュトークン、アプリの生体認証再ロック
- [ ] **1-3 権限ミドルウェア**: テナント固定、ロール判定、拠点範囲の強制。権限マトリクスの単体テスト
- [ ] **1-4 暗号化**: Key Vault のテナント別鍵でカード番号・画像を暗号化。HMAC検索列。Blob の署名付きURL発行
- [ ] **1-5 監査ログ**: 全変更系と画像閲覧を記録

### 登録者とカード
- [ ] **1-6 persons ルーター**: 一覧(検索・絞り込み・ページング)、作成、更新、退職、アーカイブ
- [ ] **1-7 カード登録ウィザード(アプリ)**: 表面撮影 → 番号確認 → IC読取 → サーバーで署名検証と照合 → 裏面撮影 → 保存。例外(IC読めない/署名失敗/差分あり)の分岐
- [ ] **1-8 IC再検証**
- [ ] **1-9 失効照会(半自動)**: アプリ内ブラウザで照会ページを開き、番号と満了日を表示、結果を記録。交付当日は翌日再照会アラート。スクレイピングはしない
- [ ] **1-10 CSV一括取込(Web)**: プレビューとエラー行表示

### 期限管理
- [ ] **1-11 期限区分の計算**: 期限切れ/30日以内/90日以内/更新申請中(特例期間)/IC未検証/要確認。JST基準。単体テスト
- [ ] **1-12 ダッシュボード(アプリ・Web)**
- [ ] **1-13 アラートジョブ**: 90/60/30日前・当日。Expo Push とメール。送信失敗の再送
- [ ] **1-14 確認履歴の出力**: CSV / PDF

### 組織と課金
- [ ] **1-15 組織管理(Web)**: 拠点、招待、権限
- [ ] **1-16 日次人数記録と月次確定**: `daily_counts` → `billing_periods.peak_count`。料金計算(基本料+単価/段階制/個別単価)の単体テスト
- [ ] **1-17 Stripe連携**: Checkout、2価格のサブスクリプション、Billing Meter(Last)への月末送信、Webhook、カスタマーポータル、適格請求書の項目設定
- [ ] **1-18 未払い時の制御**: 猶予期間後は新規登録のみ停止(閲覧とアラートは継続)
- [ ] **1-19 運営者コンソール**: テナント、プラン、個別単価
